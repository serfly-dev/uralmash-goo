# Уралмаш ГОО — первичная настройка

## Стек

- React и Next.js — веб-интерфейс.
- Express — отдельный API на порту `4000`.
- SQLite — локальная база `data/site.sqlite`.

Текущая версия включает первичные функции админ-панели: управление записями каталога и контентных разделов, заявки и загрузку медиа. Публичный frontend и его предметные страницы пока не реализованы.

## Запуск

Требуется Node.js 22.5 или новее.

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. API доступен на `http://localhost:4000/api/health`.

Можно запускать части отдельно: `npm run dev:web` и `npm run dev:api`.

## Проверка сборки

```bash
npm run build
```

SQLite использует встроенный модуль `node:sqlite` Node.js и флаг `--experimental-sqlite`; отдельный пакет для базы не требуется. Путь к базе можно переопределить переменной `SQLITE_PATH`, порт API — `API_PORT`.

## Админ-панель

Откройте `http://localhost:3000/admin/login`. Локальная учётная запись хранится в `.env.local` и создаётся в SQLite при первом запуске API. Файл `.env.local` исключён из Git. Если файл учётных данных отсутствует, скопируйте `.env.example` в `.env.local` и задайте уникальный пароль длиной не менее 12 символов. Учётные данные в файле применяются только при первом создании администратора; смена пароля и управление учётной записью через интерфейс пока не реализованы.

Сессия хранится на сервере в SQLite; браузер получает случайный HttpOnly cookie с ограниченным сроком действия. Вход ограничивает число попыток, API админ-панели проверяет сессию, а запросы входа и выхода принимаются только с адреса `APP_ORIGIN`. В production cookie автоматически получает флаг `Secure`, поэтому сайт должен работать по HTTPS.

Доступны вход, управление разделами, обработка статусов заявок и медиатека. Данные разделов хранятся в `admin_content` как JSON payload; структура payload и маршруты API описаны ниже. Публичный интерфейс магазина ещё не подключён к этим API.

## Административный API (первый контракт)

Все административные маршруты требуют действующую сессию `uralgoo_admin`. Мутации дополнительно проверяют `Origin: APP_ORIGIN`; запросы с другого источника отклоняются.

- `GET /api/admin/content/{products|categories|tags|specifications|services|reviews|works|contacts}` — список записей.
- `POST` на тот же адрес — создать запись `{slug,title,payload,published,sortOrder}`.
- `PUT` и `DELETE /api/admin/content/{type}/{id}` — изменить или удалить запись.
- `GET /api/admin/requests`, `PUT /api/admin/requests/{id}` с `{status}` — обращения и статусы `Новая`, `В работе`, `Обработана`.
- `POST /api/admin/media` — загрузить файл в raw request body; `Content-Type` должен быть JPEG, PNG, WebP, MP4 или WebM. Имя передаётся в `X-File-Name`; ответ содержит публичный URL `/media/{random-name}`. Ограничение — 100 МБ.
- `GET /api/admin/media` — список загруженных файлов.
- `GET /api/public/{type}` — только опубликованные записи для будущего сайта.
- `GET /api/public/products/{productSlug}` — карточка товара в форме `{product}`; объект содержит варианты с готовыми `href`, наследуемыми медиа/характеристиками и `priceFromRub`.
- `GET /api/public/products/{productSlug}/variants/{variantSlug}` — форма `{product, variant}` с тем же объектом товара и выбранным вариантом. Неопубликованные товары и неизвестные варианты возвращают `404`.
- `POST /api/callback` с `{name,phone}` — сохранить обращение. Почтовое уведомление пока не настроено; API возвращает это явно.

`payload` — объект раздела, чтобы сохранять предметные поля без миграции таблицы при каждом изменении контентной модели. Для товара используется `variants: [{slug, priceRub, article, characteristics, media}]`; цена варианта задаётся целым числом рублей. `categoryIds` и `tagIds` связывают товар с разделами и тегами; `featuredOnHome` отмечает товар для подборки главной страницы (frontend ограничивает подборку шестью позициями). Характеристики остаются JSON-объектами. Фото и видео выбираются из медиатеки; в записи сохраняются их публичные URL. Для отрисовки товара frontend показывает минимум `variants[].priceRub` как цену «от», а каждая страница варианта строится по адресу вида `/product/{product.slug}/{variant.slug}`. Это стартовый контракт: характеристики, фильтры и связи могут быть переведены в отдельные таблицы без изменения маршрутов API после согласования модели каталога.

Для категории задаются `parentId` и `filterSpecificationIds`. Сервер проверяет, что родитель существует, и запрещает вложение категории в себя или её потомка. В админке основные поля редактируются отдельными формами; сложные характеристики и медиасписки доступны в сворачиваемых JSON-полях.
