# Уралмаш ГОО — первичная настройка

## Стек

- React и Next.js — веб-интерфейс.
- Express — отдельный API на порту `4000`.
- SQLite — локальная база `data/site.sqlite`.

Текущая версия включает публичные страницы главной, каталога и вариантов оборудования, направлений, проектов, о компании и контактов, а также админ-панель для управления содержимым, заявками и медиа.

## Запуск

Требуется Node.js 22.5 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который показывает Next.js (обычно `http://localhost:3000`). API доступен на `http://localhost:4000/api/health`.

Можно запускать части отдельно: `npm run dev:web` и `npm run dev:api`.

## Проверка сборки

```bash
npm run build
```

SQLite использует встроенный модуль `node:sqlite` Node.js и флаг `--experimental-sqlite`; отдельный пакет для базы не требуется. Путь к базе можно переопределить переменной `SQLITE_PATH`, порт API — `API_PORT`.

## Админ-панель

Откройте `/admin/login` на адресе, который показывает Next.js. Локальная учётная запись хранится в SQLite и синхронизируется с `.env.local` при каждом запуске API в режиме разработки; пароль должен содержать не менее 6 символов. В production пароль применяется только при первом создании администратора и должен содержать не менее 12 символов. `.env.local` исключён из Git; если файла нет, скопируйте `.env.example` и задайте собственные учётные данные. Смена пароля через интерфейс пока не реализована.

Сессия хранится на сервере в SQLite; браузер получает случайный HttpOnly cookie с ограниченным сроком действия. Вход ограничивает число попыток, API админ-панели проверяет сессию, а запросы входа и выхода принимаются только с адреса `APP_ORIGIN`. В production cookie автоматически получает флаг `Secure`, поэтому сайт должен работать по HTTPS.

Доступны вход, управление разделами, обработка статусов заявок и медиатека. Данные разделов хранятся в `admin_content` как JSON payload; публичные страницы получают только опубликованные записи через API.

## Административный API (первый контракт)

Все административные маршруты требуют действующую сессию `uralgoo_admin`. Мутации дополнительно проверяют `Origin: APP_ORIGIN`; запросы с другого источника отклоняются.

- `GET /api/admin/content/{products|categories|tags|specifications|services|reviews|works|contacts}` — список записей.
- `POST` на тот же адрес — создать запись `{slug,title,payload,published,sortOrder}`.
- `PUT` и `DELETE /api/admin/content/{type}/{id}` — изменить или удалить запись.
- `GET /api/admin/requests`, `PUT /api/admin/requests/{id}` с `{status}` — обращения и статусы `Новая`, `В работе`, `Обработана`.
- `POST /api/admin/media` — загрузить файл в raw request body; `Content-Type` должен быть JPEG, PNG, WebP, MP4 или WebM. Имя передаётся в `X-File-Name`; ответ содержит публичный URL `/media/{random-name}`. Видео ограничено 100 МБ, статичные изображения — 25 МБ и 50 мегапикселями; изображения декодируются, поворачиваются по EXIF, уменьшаются до 2560 px и сохраняются в WebP. Анимированные изображения отклоняются с сообщением об ошибке. Общий лимит хранилища задаётся `MEDIA_STORAGE_LIMIT_MB` (по умолчанию 5120 МиБ).
- `GET /api/admin/media` — список загруженных файлов.
- `DELETE /api/admin/media/{id}` — удалить файл, только если он не используется ни в одной записи. Используемые и неразбираемые ссылки защищены от удаления.
- `GET /api/public/{type}` — только опубликованные записи для будущего сайта.
- `GET /api/public/products/{productSlug}` — карточка товара в форме `{product}`; объект содержит варианты с готовыми `href`, наследуемыми медиа/характеристиками и `priceFromRub`.
- `GET /api/public/products/{productSlug}/variants/{variantSlug}` — форма `{product, variant}` с тем же объектом товара и выбранным вариантом. Неопубликованные товары и неизвестные варианты возвращают `404`.
- `POST /api/callback` принимает `{name, phone, consent, intent, sourcePath, message?, serviceSlug?, productSlug?, variantSlug?}`; `intent` — `repair`, `purchase` или `general`. Личные данные шифруются AES-256-GCM до записи в SQLite, а админ-панель расшифровывает их после проверки сессии. Лимит — две заявки с одного IP за скользящую минуту.

`payload` — объект раздела, чтобы сохранять предметные поля без миграции таблицы при каждом изменении контентной модели. Для товара используется `variants: [{slug, priceRub, article, characteristics, media}]`; цена варианта задаётся целым числом рублей. `categoryIds` и `tagIds` связывают товар с разделами и тегами; `featuredOnHome` отмечает товар для подборки главной страницы (frontend ограничивает подборку шестью позициями). Характеристики остаются JSON-объектами. Фото и видео выбираются из медиатеки; в записи сохраняются их публичные URL. Для отрисовки товара frontend показывает минимум `variants[].priceRub` как цену «от», а каждая страница варианта строится по адресу `/catalog/product/{product.slug}/{variant.slug}`. Это стартовый контракт: характеристики, фильтры и связи могут быть переведены в отдельные таблицы без изменения маршрутов API после согласования модели каталога.

Серверный рендеринг каталога, товара, услуг, проектов и контактов использует `API_INTERNAL_URL` (по умолчанию `http://localhost:4000`). Для production задайте `NEXT_PUBLIC_SITE_URL` на публичный HTTPS адрес сайта: он используется в canonical, Open Graph и sitemap. `/admin` исключён из индексации через metadata и `robots.txt`; эти настройки не заменяют авторизацию.

### Почтовые уведомления о заявках

Сменить пароль можно в админ-панели: сначала подтвердите действие кодом из письма, затем введите текущий и новый пароль. Код отправляется на адрес `SMTP_TO`, поэтому нужны включённые и работающие настройки почты. После смены пароля все сеансы завершаются. Значения `ADMIN_USERNAME` и `ADMIN_PASSWORD` используются только при создании учётной записи и не перезаписывают её при перезапуске.

По умолчанию уведомления выключены. Для включения задайте `MAIL_NOTIFICATIONS_ENABLED=true`, все `SMTP_*` параметры в `.env.local` и HTTPS адрес сайта в `APP_ORIGIN`. Используйте SMTP выбранного владельцем российского почтового провайдера, его пароль приложения и адрес получателя. Не добавляйте пароль в Git и не отправляйте тестовые письма без согласованного адреса и SMTP-настроек. Если уведомления включены без полной SMTP-конфигурации, заявки попадут в локальную SQLite-очередь и дождутся исправления настроек; при выключенном флаге очередь не создаётся.

В письмо включены только факт новой заявки и ссылка `${APP_ORIGIN}/admin`; данные заявки, её ID и токены не отправляются. API сначала сохраняет заявку и запись очереди в одной транзакции SQLite, а затем отдельный процесс отправляет письмо с повторными попытками. Отметка об отправке означает, что SMTP-сервер принял письмо, но не подтверждает его доставку в почтовый ящик. При отказе SMTP заявка остаётся в админ-панели; причина и содержимое ответа SMTP не записываются в логи. После обрыва процесса в момент отправки возможна повторная доставка уже принятого письма.

Для категории задаются `parentId` и `filterSpecificationIds`. Сервер проверяет, что родитель существует, и запрещает вложение категории в себя или её потомка. В админке основные поля редактируются отдельными формами; сложные характеристики и медиасписки доступны в сворачиваемых JSON-полях.
